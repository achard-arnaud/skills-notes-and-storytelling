# Capacités et limites vérifiées

## Exécuté

- Audit ciblé source/cible, 72 microtickets et huit epics liés sur GitHub.
- Import Markdown déterministe, localisateurs et empreintes ; validation contractuelle de références, statuts, liens et revues ; projection de graphe.
- Board DAG, paquets de contexte bornés, checkpoint et détection d'entrées périmées ; invalidation ciblée disponible comme fonction.
- HTML autonome avec navigation par récit/piliers/preuves/side stories ; tests statiques liens/échappement/états.
- Reprise indépendante depuis capsule/paquet, sans historique de conversation.

## Toujours distinct de ces contrôles

- Le compteur mesure les corps des fichiers déclarés. Les instructions racine/routées/compagnons doivent être énumérés ; ni système, ni chat ni tokens exacts ne sont mesurés.
- Les write scopes, limites de réparation et writer unique sont un protocole coordonné, pas des leases/verrous distribués exécutables.
- L'import segmente par blocs textuels, pas en propositions sémantiques atomiques. Claims importés = supplied_claim. Aucune corroboration automatique.
- Le schéma de fait vérifié exige une qualification/revue déclarée ; il ne détecte pas un reviewer mensonger ou une source primaire inappropriée au scope.
- ResearchMap et scénarisation restent des méthodes/documentation ; pas de moteur autonome de recherche ou de rédaction. Le graphe probatoire ne génère pas la causalité ni le récit.
- HTML Mermaid = source explicite sans moteur distant. QA navigateur/visuelle bloquée par l'environnement ; tests statiques seulement.
- GitHub Issues et board versionné sont réels ; aucune instance Jira ni GitHub Projects modifiée.
- Aucune compaction/purge technique de fenêtre, worker persistant, automation ou nouveau backend installé.
- Conversation liée inaccessible ; import privé limité aux deux documents disponibles. Ni l'entretien ni l'annonce originale ne sont déclarés intégralement récupérés.
- Piliers, trame et side stories candidats à valider par François. Tests ≠ validation humaine.
