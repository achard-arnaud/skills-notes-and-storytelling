# Personal branding

## Selection

Resolve branding in this order:

1. explicit `profile_id` in the output specification;
2. profile unambiguously identified by the project context;
3. `default_profile` from `branding/profiles.json`.

The default profile is `francois`. Add another person as one atomic entry under `profiles`; do not duplicate or fork document templates. Use `enabled: false` when personal branding is inappropriate.

## Header

Keep the header to one compact line:

- left: document object;
- right: template, version and date.

## Footer

Use at most two compact lines:

- identity: display name, headline, optional organization/capacity and profile link;
- themes, provenance link and page number.

Use short link labels instead of displaying full URLs. Branding must not compete with the document conclusion.

## Content style

Convert enumerations of three or more items into bullets. Use numbered lists only when order, sequence or priority matters. Keep prose when the items form one causal sentence rather than a scan-oriented list.

## Data boundary

Branding is presentation metadata. It must not become evidence for business claims, author credentials or client relationships inside the note.
