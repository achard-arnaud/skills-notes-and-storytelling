# Runtime profiles

Four independent controls: environment (chat/work), execution (light/heavy), debug (on/off),
generation (from-scratch/iterative/feedback-dreaming). Cowork normalizes to work.
Debug changes observability, not evidence standards. Documents override light to heavy with a reason.
If attachments cannot be read, report the blocked material; never silently substitute web evidence.

Configurable starting budgets, not measured host limits:

| Environment | No document | Packet target | Initial gap queries |
|---|---|---|---|
| chat | light | 2,000 words | 3 |
| work | heavy | 6,000 words | 6 |

Record budget overrides. Required evidence cannot be dropped to fit: return overflow and split by
section, preserving contradictions/dependencies. Heavy chat uses successive packets and checkpoints.
Reasoning: low for deterministic formatting/extraction; medium for simple synthesis; high for
contradictions, multiple entities, economic/causal comparisons or source ambiguity. Escalate affected
claims only. This is a recommendation: the host may not expose reasoning/model settings. Never claim
settings changed without an actual API/tool action. A skill does not itself select models or spawn agents.

From scratch starts an empty prose baseline but can reuse original sources after freshness review.
Iterative requires baseline_id and targets; append revisions. Writing-only keeps factual approval;
form-global reopens all paragraphs in selected sections. Feedback proposes fixture-backed changes.

Cost evaluation logs actual model/tokens when exposed, elapsed time, read paths, searches, packet
words, reruns and QA failures. Words are proxies, not billed tokens. Compare equal tasks and quality
gates; do not promise percentage savings or serialize full documents/debug logs into every prompt.
